# Todo-Lite PRD

## 1. 개요

- 제품명(가칭): **Todo-Lite**
- 한 줄 설명: 자연어 한 줄로 할 일을 입력하면 마감일·우선순위·태그가 자동으로 정리되는, 가볍고 오프라인 우선인 개인용 투두 앱
- 대상 사용자: 본인 1인 (개인용, 멀티 유저 없음)

## 2. 목표 / 비목표

### 목표

- 빠른 입력: 한 줄 입력과 엔터 한 번으로 구조화된 할 일 생성
- 가벼움: 설치 파일 < 50MB, 시작 시간은 빈 Tauri 앱 대비 +0.5초 이내(절대 시간은 PC의 WebView2 시작 속도에 좌우됨), 유휴 메모리 ~100MB 이하 (WebView2 포함)
- 오프라인 우선: 인터넷 없이 모든 기능 동작
- 확장성: 코어 로직을 UI·플랫폼과 분리해서 Android와 AI 파서를 코드 재작성 없이 추가

### 비목표 (MVP 제외)

- 알림, 반복 일정, 하위 할 일 → v2
- Android 빌드 → v3 (구조만 대비)
- LLM 기반 파싱 → 플러그인으로 이후 추가
- 다중 사용자, 공유, 계정, 자체 서버

## 3. 플랫폼 & 기술 스택

- 대상: Windows 데스크톱 (MVP), Android (v3, Tauri 2 모바일 타깃)
- 앱 셸: Tauri 2
- 프론트엔드: Svelte 5 + TypeScript + Vite
- 코어: Rust 라이브러리 크레이트 `todo-core`
  - 저장: SQLite (`rusqlite`, bundled)
  - 날짜: `chrono`
  - ID: `uuid` v7 (시간 순 정렬 가능)
  - 직렬화: `serde` / `serde_json`

## 4. 아키텍처

```
todolist/
├─ crates/todo-core/      # 순수 Rust, UI 의존성 없음 (Android에서 재사용)
│   ├─ model.rs           # Task, Priority, Tag
│   ├─ store.rs           # TaskStore trait + SQLite 구현
│   ├─ parser/            # TaskParser trait + RuleBasedParser (한국어)
│   ├─ query.rs           # 오늘/예정/지난/검색 필터
│   └─ sync/              # 변경 로그 기록·병합
├─ src-tauri/             # Tauri 커맨드: 코어를 얇게 감싸는 계층
└─ ui/                    # Svelte 화면
```

- 핵심 원칙: `todo-core`는 Tauri를 모른다. Tauri 커맨드는 코어 함수를 호출만 한다.
- 확장 지점이 되는 trait
  - `TaskParser { fn parse(&self, input: &str, now: NaiveDateTime) -> ParsedTask }`
    - 이후 `ClaudeParser`나 `LocalLlmParser`를 추가하고, 실패하면 규칙 기반으로 폴백한다.
  - `TaskStore`: 저장소 교체 가능

## 6. 기능 요구사항 (MVP)

### F1. 할 일 기본 관리

추가, 수정, 삭제, 완료/완료 취소. 완료 항목은 별도 섹션에 접어서 표시한다.

### F2. 자연어 빠른 입력 (규칙 기반)

- 입력창에 타이핑하는 동안 인식 결과를 칩(마감·우선순위·태그)으로 **실시간 미리보기**한다. 엔터를 누르면 저장한다.
- 인식 규칙
  - 상대 날짜: 오늘, 내일, 모레, 글피, N일 후/뒤, 다음 주, 이번 주 금요일, 다음 주 월요일
  - 절대 날짜: `10월 30일`, `10/30`, `2026-10-30`
  - 시간: `오후 3시`, `3시 반`, `15:00`, `아침`(09:00), `점심`(12:00), `저녁`(19:00)
  - 우선순위: `!높음`, `!중요`, `!!` → High / `!낮음` → Low
  - 태그: `#학교`, `#개인` (여러 개 가능)
  - 인식된 토큰을 뺀 나머지가 제목
- 예: `내일 오후 3시 팀플 회의 #학교 !중요`
  - 제목 "팀플 회의", 마감 내일 15:00, 태그 [학교], 우선순위 High
- 날짜 없이 시간만 입력하면 **오늘**의 그 시각으로 해석한다. 이미 지난 시각이어도 내일로 넘기지 않는다. (예측 가능성 우선. 사용자는 미리보기 칩에서 확인하고 고칠 수 있다.)

### F3. 마감일/시간

날짜 선택기로 수동 편집할 수 있다. 날짜만 지정하거나 날짜와 시간을 함께 지정한다.

### F4. 우선순위

3단계. 목록 안에서 같은 마감일이면 우선순위 순으로 정렬한다.

### F5. 태그

사이드바에 태그 목록을 표시하고, 클릭하면 필터링한다. 입력 시 자동완성을 제공한다.

### F6. 검색

제목·메모·태그 부분 일치. `Ctrl+F`

### F7. 보기(뷰)

- 오늘: 오늘 마감과 지난 마감(미완료)
- 예정: 내일 이후
- 지난 일: 마감이 지났는데 미완료
- 전체 / 완료됨

### F8. 메모

할 일 상세 패널에서 여러 줄 텍스트를 편집한다.

### F9. 클라우드 폴더 동기화

- 설정에서 동기화 폴더 경로를 지정한다. (Google Drive, OneDrive 등 로컬 동기화 폴더)
- 기기마다 고유 `device_id`를 두고, 자기 파일 `sync/<device_id>.jsonl`에만 **추가 기록**(append-only 변경 로그)한다.
- 다른 기기의 `.jsonl`을 읽어 로컬 SQLite에 병합한다. 기기별로 읽은 위치(오프셋)를 기억한다.
- 충돌 규칙: 할 일 단위 **Last-Write-Wins** (`updated_at`, 같으면 `device_id`로 결정). 삭제는 삭제 표시로 전파한다.
- 동기화 시점: 앱 시작 시, 변경 직후(디바운스 2초), 5분 주기, 수동 버튼
- 동기화 폴더를 지정하지 않으면 로컬 전용으로 동작한다.
- Android에서는 앱이 직접 클라우드 API를 호출하지 않는다. Syncthing이나 FolderSync 같은 외부 앱이 폰의 로컬 폴더를 같은 폴더와 맞춘다. (v3)

### F10. 키보드 우선 UX

`Ctrl+N` 빠른 입력, `↑/↓` 이동, `Space` 완료, `Enter` 편집, `Del` 삭제

### F11. 트레이 상주

- X 버튼은 창을 숨기고, 앱은 트레이에서 계속 실행된다.
- 트레이 아이콘 왼쪽 클릭: 창 열기/숨기기. 오른쪽 메뉴: 열기 / 빠른 추가 / 종료.
- 앱을 끝내는 방법은 트레이 "종료"뿐이다.
- 앱을 두 번 실행하면 새로 뜨지 않고 기존 창을 앞으로 가져온다.
- 설정에서 "Windows 시작 시 자동 실행"을 켤 수 있다. 기본은 꺼짐이고, 켜면 로그인할 때 창 없이 트레이로 시작한다.

### F12. 전역 단축키 빠른 입력창

- 기본 단축키는 `Ctrl+Alt+Space`이다. 설정에서 바꿀 수 있고, 수정자 키(Ctrl·Alt·Shift)가 하나 이상 있어야 하며 키는 A–Z, 0–9, F1–F12, Space 중에서 고른다.
- 다른 프로그램을 쓰는 중에도 단축키를 누르면 작은 입력창이 뜨고, 입력하는 동안 칩 미리보기가 보인다.
- 입력창은 마우스 커서가 있는 모니터의 아래쪽 가운데(작업 표시줄 바로 위, 작업 표시줄을 가리지 않음)에 뜬다.
- Enter로 저장하면 창이 닫힌다. Esc를 누르거나 다른 곳을 클릭해도 닫힌다.
- 저장하면 메인 목록이 즉시 갱신된다.
- 단축키 등록에 실패하면(다른 프로그램과 충돌 등) 설정 화면에 이유를 보여 준다. 트레이 메뉴의 "빠른 추가"는 계속 쓸 수 있다.

## 7. 비기능 요구사항

- 성능: 할 일 1만 개에서 목록·검색 응답 < 100ms
- 신뢰성: 로컬 쓰기는 SQLite 트랜잭션으로 처리한다. 동기화 파일이 깨져도 로컬 데이터는 무손실이어야 한다. (문제가 있는 줄은 건너뛰고 로그로 남긴다.)
- 프라이버시: 데이터는 로컬과 사용자 지정 폴더에만 존재한다. 네트워크 호출 없음.
- 테스트: `todo-core`는 단위 테스트를 갖춘다. (특히 파서의 한국어 날짜 케이스, 동기화 병합 시나리오)

## 8. 로드맵

- **v1 (MVP)**: F1–F10, Windows
- **v2**: 알림, 반복 일정, 하위 할 일, JSON 내보내기/가져오기
- **v3**: Android 빌드 (Syncthing/FolderSync 폴더 연동 가이드)
- **AI 확장 (선택)**: `TaskParser` 구현체 추가. Claude API(Haiku 계열) 또는 로컬 소형 LLM. 규칙 파서 결과가 불확실할 때만 호출하는 하이브리드 방식

## 9. 성공 기준

- 일상적인 입력 문장의 90% 이상이 수정 없이 올바르게 파싱된다. (테스트 케이스 50개 이상)
- 두 기기에서 같은 폴더로 동기화할 때 데이터 유실이나 중복이 없다.
- 위 성능·용량 목표를 충족한다.

## 10. 구현 상태 (v1 데스크톱)

- 화면: 사이드바·목록·상세 3단, 다크 고정.
- 키보드: Ctrl+N / Ctrl+F / ↑↓ / Space / Enter / Del / Esc
- 측정 (Windows, 릴리스 빌드, `scripts/measure.ps1` 2회 실행 + 앞선 독립 측정 3회가 일치):

| 항목 | 목표 | 실측 | 판정 |
|---|---|---|---|
| 설치 파일 | < 50 MB | 3.0 MB | 달성 |
| 유휴 메모리 (WebView2 포함, 프라이빗 작업 집합 합계)* | 약 100 MB 이하 | 79-82 MB (앞선 측정 73-82 MB) | 달성 |
| 시작 → 첫 화면 (빈 Tauri 앱 대비 추가 시간) | +0.5 s 이내 | 중앙값 +0.32~0.35 s (절대값 약 2.0 s, 빈 앱 약 1.6 s) | 달성 |
| 1만 건 목록·검색 | < 100 ms | 약 44 ms (코어 perf 테스트, 릴리스) | 달성 |

\* 같은 시점의 커밋(프라이빗 바이트) 합계 약 124-133 MB와 공유 페이지를 중복 계산한 작업 집합 합계 약 303-317 MB는 서로 다른 지표이며, 위 목표가 가리키는 값이 아니다.

시작 시간 목표는 처음에 절대값 "< 1초"였으나 달성하지 못했고, 아래 조사 결과에 따라 2026-10-30에 "빈 Tauri 앱 대비 +0.5초 이내"라는 상대 기준으로 바꿨다. 조사는 이 PC 한 대에서 릴리스 빌드로 했고 결과는 다음과 같다(`scripts/startup-trace.ps1`, 우리 앱과 빈 Tauri 앱을 번갈아 10라운드, 웜 9회 기준 중앙값).

- 기능이 전혀 없는 빈 Tauri 앱(정적 페이지 하나)도 시작부터 페이지 로드 완료까지 중앙값 약 1.6초(최소 약 1.4초)가 걸렸다. 우리 앱은 중앙값 약 2.0초였다.
- 우리 앱이 더하는 시간은 중앙값 약 0.3~0.35초이고, 나머지 약 80%는 Tauri가 창과 WebView2를 만드는 구간이다. 이 구간에서는 우리 코드가 실행되지 않는다.
- WebView2 프로필을 데워도 빨라지지 않았다(콜드와 웜이 비슷).
- 따라서 이 PC에서는 기본 WebView2 시작 경로로 1초 미만을 달성할 수 없다. 다른 PC에서의 값은 측정하지 않았다.
- 한계: 한 번의 배치이고 라운드별 편차가 크다(우리−빈 앱 차이가 −0.04~+1.3초). 우리가 더하는 0.3~0.35초의 세부 원인(설정 단계, 더 큰 실행 파일, 번들 로딩)은 아직 가설이다.

새 기준(빈 Tauri 앱 대비 +0.5초 이내)에서는 중앙값 +0.32~0.35초로 달성이다. 절대 1초 미만이 꼭 필요하면 WebView2를 쓰지 않는 네이티브 UI(예: Slint) 검토가 필요하지만, 화면 전체를 다시 써야 하므로 지금은 하지 않는다.

### 트레이·빠른 입력창 실측

Windows, 릴리스 빌드(`npx tauri build --no-bundle`), 2026-10-31, 이 PC 한 대. 빠른 입력창은 처음 쓸 때 만들어서 숨겨 두고 재사용하는 지연 생성 방식이다.

- 빠른 창 첫 표시 지연 (`scripts/smoke-tray.ps1` 5회, 시작 3초 뒤 자동 호출한 시점부터):

| 구간 | 중앙값 | 최소 | 최대 |
|---|---|---|---|
| 호출 → 창 표시 (`quick_trigger_to_shown_ms`) | 465 ms | 384 ms | 531 ms |
| 호출 → 화면 로드 완료 (`quick_trigger_to_page_finished_ms`) | 586 ms | 541 ms | 682 ms |

  처음 한 번만 걸리는 값이다. 이후에는 숨겨 둔 창을 다시 보여 주므로 이 지연이 없다(이 값은 재사용 시간을 따로 측정하지 않았다). 창이 먼저 보이고 화면이 약 0.15초 뒤에 그려진다.

- 메모리 (`scripts/measure.ps1` 방식, 시작 20초 뒤, 프라이빗 작업 집합 합계, 2회씩):

| 상태 | 프로세스 수 | 프라이빗 작업 집합 | 목표(약 100 MB 이하) |
|---|---|---|---|
| 빠른 창 없음 (메인만) | 7 | 82 MB, 78 MB | 달성 |
| 빠른 창 생성 후 (숨겨 둔 상태 포함) | 8 | 100 MB, 99 MB, 105 MB (3회) | 경계선~약간 초과: 3회 중 1회는 목표를 넘음 |

  빠른 창이 웹뷰 프로세스를 하나 더 띄워 약 17~22 MB를 더한다. 같은 시점의 커밋 합계는 123~130 MB에서 153~157 MB로 늘었다. 목표를 맞추려고 코드를 바꾸지 않았고 측정값을 그대로 적었다. 빠른 창을 한 번도 쓰지 않으면 메인만 있는 수치와 같다.

### 검증 상태

- 자동 테스트: Rust 코어 74 + 앱 9, 화면 로직(Vitest) 전체 통과. 앱이 뜨고 데이터를 불러와 첫 화면을 그리는 것은 스크린샷으로 확인했다.
- 사람의 직접 확인(2026-10-30): 사용자가 앱을 직접 써 보고 삭제 확인창을 제외한 나머지 기능은 작동한다고 알려 왔다. 어떤 항목을 확인했는지는 항목별로 기록하지 않았다.
- 발견된 버그(2026-10-30): Tauri dialog 플러그인이 `window.confirm`을 비동기로 바꿔서 "아니요"를 눌러도 삭제되고, 확인창이 Windows 기본 메시지 상자처럼 보였다. 앱 안의 자체 확인창으로 교체해 고쳤고, "아니요를 누르면 삭제하지 않는다"는 회귀 테스트를 추가했다. 교체 후 실제 화면에서 다시 확인하는 것은 사용자의 몫으로 남아 있다.
- 자동 스모크(`scripts/smoke-tray.ps1`, 화면 입력 없음): X(WM_CLOSE) 요청 시 프로세스가 살아 있고 메인 창만 숨겨지는지(트레이 상주), 빠른 창이 교착 없이 뜨고 닫기 요청 시 숨겨지는지, 트레이·전역 단축키용 도우미 창이 존재하는지를 확인한다. 릴리스 빌드에서 5회 모두 9/9 통과했다. 자동으로 확인하지 못했고 사용자의 직접 확인이 남은 것: 실제 트레이 아이콘 클릭과 메뉴, 다른 프로그램에서 실제 전역 단축키를 눌렀을 때의 포커스·타이핑, 빠른 창의 한글 입력기(IME), 다른 곳을 클릭하면 닫히는 동작, 앱을 두 번 실행했을 때 기존 창 앞으로 가져오기, 설정에서 단축키 변경, 재로그인 뒤 자동 실행(설치한 빌드에서만 의미가 있음).
